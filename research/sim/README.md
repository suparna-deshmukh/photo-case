# Simulated participant study (R2-sim)

**STATUS: SIMULATED — not real users.** Six participant profiles and their interview
answers were generated by an AI model (agent 3, 2026-10-06) by running the exact R1
interviewer script (`research/interview_kit/interviewer_script_friend.md`) against six
designed profiles. Generated by `code/sim_study.py` (single source of truth for the
transcripts and `research/notes_simulated.csv`).

## Why this exists
1. **Protocol validation** — run the full A-E protocol + reverse-recall probe end-to-end
   to find questions that are confusing, codebook gaps, and Note Sheet fields that are
   hard to fill, BEFORE the real friend sessions.
2. **Codebook coverage check** — every cue_type, failure_gate, query_style, workaround
   and outcome enum in the R1 codebook should appear at least once (checked in the cards).
3. **Scenario generation** — the 3 most common retrieval scenarios (task cards) seed
   deck narrative and future M5-style task design.

## Hard constraints (integrity)
- NEVER cite these transcripts, quotes, or numbers in the deck as user evidence.
- Deck may only mention them as: "interview protocol validated on 6 simulated
  participants (AI-generated); real evidence = discovery engine + n real probe
  recordings from the pilot cohort (friends, solo think-aloud videos)".
- When the friend videos arrive, they REPLACE/validate this study; the synthesis is
  re-run on `research/notes.csv` (real) and this folder is kept as the validation artifact.
